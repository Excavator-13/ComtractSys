# 合同管理系统接口文档

## 1. 通用约定

### 1.1 基础路径

```text
/api/v1
```

### 1.2 鉴权

除注册、登录外，接口需携带：

```http
Authorization: Bearer <jwt-token>
```

### 1.3 统一响应

```json
{
  "code": 0,
  "message": "success",
  "data": {}
}
```

### 1.4 分页响应

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "records": [],
    "page": 1,
    "size": 10,
    "total": 100
  }
}
```

## 2. 认证接口

### 2.1 注册

`POST /api/v1/auth/register`

```json
{
  "username": "zhangsan",
  "password": "123456",
  "confirmPassword": "123456"
}
```

响应：

```json
{
  "code": 0,
  "message": "注册成功",
  "data": {
    "userId": 1,
    "username": "zhangsan"
  }
}
```

### 2.2 登录

`POST /api/v1/auth/login`

```json
{
  "username": "admin",
  "password": "123456"
}
```

响应：

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "token": "jwt-token",
    "user": {
      "id": 1,
      "username": "admin",
      "displayName": "管理员",
      "roles": ["ROLE_ADMIN"],
      "permissions": ["user:manage", "contract:assign"]
    }
  }
}
```

### 2.3 当前用户

`GET /api/v1/auth/me`

返回当前用户、角色、权限点和前端菜单。

### 2.4 登出

`POST /api/v1/auth/logout`

JWT 方案下前端清理 Token 即可；如引入 Token 黑名单，则后端记录失效 Token。

## 3. 用户、角色、权限接口

### 3.1 用户分页查询

`GET /api/v1/users?page=1&size=10&keyword=zhang&status=ENABLED`

### 3.2 新增用户

`POST /api/v1/users`

{
  "username": "lisi",

  "displayName": "李四",
  "phone": "13800000000",

## 5. 合同接口

### 5.1 合同分页查询

`GET /api/v1/contracts?page=1&size=10&keyword=采购&status=DRAFT&customerId=1`

### 5.2 合同详情

`GET /api/v1/contracts/{id}`

返回合同基础信息、客户、附件、状态历史、流程任务。

### 5.3 起草合同

`POST /api/v1/contracts`

请求类型：`multipart/form-data`

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| name | string | 是 | 合同名称 |
| customerId | number | 是 | 客户 ID |
| beginDate | date | 是 | 开始日期 |
| endDate | date | 是 | 结束日期 |
| content | string | 是 | 合同内容 |
| files | file[] | 否 | 附件 |

响应：

```json
{
  "code": 0,
  "message": "起草成功",
  "data": {
    "id": 1001,
    "contractNo": "HT202605200001",
    "status": "DRAFT"
  }
}
```

### 5.4 修改合同基础信息

`PUT /api/v1/contracts/{id}`

用于草稿修改或定稿前编辑。

### 5.5 删除合同

`DELETE /api/v1/contracts/{id}`

### 5.6 上传附件

`POST /api/v1/contracts/{id}/attachments`

### 5.7 下载附件

`GET /api/v1/contracts/{id}/attachments/{attachmentId}/download`

## 6. 合同流程接口

### 6.1 分配合同

`POST /api/v1/contracts/{id}/assign`

```json
{
  "countersignUserIds": [2, 3],
  "approvalUserIds": [4],
  "signUserIds": [5]
}
```

规则：

1. 仅 `DRAFT` 状态可分配。
2. 会签、审批、签订人员必须全部指定。
3. 分配后生成流程任务，合同状态变为 `ASSIGNED`。

### 6.2 我的待办

`GET /api/v1/tasks/my?type=COUNTERSIGN&status=PENDING&page=1&size=10`

### 6.3 会签合同

`POST /api/v1/contracts/{id}/countersign`

```json
{
  "opinion": "合同条款完整，同意进入定稿。"
}
```

规则：

1. 当前用户必须是该合同待会签人。
2. 会签意见不能为空。
3. 全部会签人完成后合同状态变为 `COUNTERSIGNED`。

### 6.4 定稿合同

`POST /api/v1/contracts/{id}/finalize`

```json
{
  "content": "定稿后的合同正文"
}
```

规则：

1. 当前用户必须是起草人或有 `contract:update` 权限。
2. 仅 `COUNTERSIGNED` 状态可定稿。
3. 定稿后合同状态变为 `FINALIZED`。

### 6.5 审批合同

`POST /api/v1/contracts/{id}/approve`

```json
{
  "result": "APPROVED",
  "opinion": "审批通过。"
}
```

`result` 可取值：`APPROVED`、`REJECTED`。

规则：

1. 当前用户必须是该合同待审批人。
2. 任一审批人拒绝，合同状态变为 `REJECTED`。
3. 全部审批人通过，合同状态变为 `APPROVED`。

### 6.6 签订合同

`POST /api/v1/contracts/{id}/sign`

```json
{
  "signInfo": "双方已于 2026-05-20 完成纸质合同签署。",
  "signedDate": "2026-05-20"
}
```

规则：

1. 当前用户必须是该合同待签订人。
2. 仅 `APPROVED` 状态可签订。
3. 签订后合同状态变为 `SIGNED`。

### 6.7 流程记录

`GET /api/v1/contracts/{id}/process`

返回流程任务和状态历史。
