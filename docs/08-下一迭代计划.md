# 下一迭代计划

更新时间：2026-05-21

## 1. 当前进度摘要

当前代码库已经完成合同管理系统的基础骨架：

| 模块 | 当前状态 |
| --- | --- |
| 项目工程 | Spring Boot 后端、Vue 3 前端、文档体系、Git 仓库已建立 |
| 认证登录 | 支持注册、登录、退出、当前用户查询 |
| RBAC 权限 | 支持用户、角色、权限点、接口级权限拦截、前端菜单/路由权限 |
| 用户角色管理 | 支持用户增删改查、启停、分配角色，角色增删改查、分配权限 |
| 客户管理 | 支持客户增删改查和列表查询 |
| 合同流程 | 支持起草、分配、会签、定稿、审批、签订、驳回后重新提交 |
| 附件与日志 | 支持附件上传下载删除、流程日志查询和 CSV 导出 |
| 测试验证 | 后端 RBAC 与边界集成测试 38 个用例，前端生产构建通过 |

## 2. 本轮发现的问题

| 优先级 | 问题 | 影响 | 建议 |
| --- | --- | --- | --- |
| P0 | JWT 已替换内存 Token，但尚未引入刷新令牌/黑名单 | 退出后旧 Token 在过期前仍可使用 | 评估刷新令牌、短有效期、Token 黑名单或用户 tokenVersion |
| P0 | Spring Security 当前 `permitAll`，权限靠 MVC 拦截器 | 对非 MVC 资源和未来接口扩展容易遗漏 | 改为 Security Filter + 方法权限，保留注解语义 |
| P0 | MySQL profile 与 Flyway 已加入，但缺少真实 MySQL 环境的 CI 校验 | 本地可联调，流水线暂未覆盖 MySQL | 增加 GitHub Actions service container 跑 MySQL profile 测试 |
| P1 | 合同编号使用时间取模 | 高并发或同毫秒存在碰撞风险 | 改为数据库序列/雪花 ID/日期流水号表 |
| P1 | 分配流程未校验人员能力 | 可把任务分给无对应业务权限的用户 | 分配时校验会签/审批/签订人员具备对应权限 |
| P1 | 待办和流程表单使用浏览器 prompt | 可用性弱，不利于复杂意见录入 | 改成弹窗表单，支持必填、字数、确认态 |
| P1 | 附件安全校验不完整 | 文件类型和内容安全风险 | 增加白名单、大小限制、MIME/扩展名双校验、下载鉴权细化 |
| P2 | 首页统计为全局统计 | 普通操作员看到的数据口径不够明确 | 增加按角色/本人维度统计 |
| P2 | 缺少 CI/CD | 每次提交需手动验证 | 增加 GitHub Actions：后端测试、前端构建 |
| P2 | 缺少部署配置 | 不便于交付和演示 | 增加 Docker Compose、环境变量示例、生产 profile |

## 3. 下一迭代建议范围

建议下一轮先做“可部署、可联调、权限更可靠”的工程化迭代。

### 3.1 P0：认证与数据库落地

目标：让系统从开发演示进入可持续联调状态。

交付项：

| 任务 | 内容 |
| --- | --- |
| AUTH-03 | 完善 JWT 退出、刷新、密钥轮换和过期策略 |
| DB-01 | 增加 MySQL profile 的 CI 覆盖 |
| DB-02 | 根据业务迭代维护后续 Flyway 版本脚本 |
| SEC-02 | 将接口保护收敛到 Spring Security Filter 或方法级权限 |

验收标准：

| 验收点 | 标准 |
| --- | --- |
| 登录稳定性 | 后端重启后无需依赖内存 Token 状态，JWT 过期策略可配置 |
| 数据持久化 | MySQL 环境可启动并保留用户、角色、合同数据，迁移脚本随版本演进 |
| 权限一致性 | 未登录 401，无权限 403，接口新增不会绕过权限策略 |

### 3.2 P1：合同流程业务约束

目标：让合同主流程更接近真实业务。

交付项：

| 任务 | 内容 |
| --- | --- |
| CON-08 | 分配人员时校验对应权限，禁止分配给禁用用户 |
| CON-09 | 优化合同编号生成，避免碰撞 |
| CON-10 | 完善审批驳回、重新提交、任务重置的状态历史 |
| CON-11 | 增加合同流程端到端集成测试 |

验收标准：

| 验收点 | 标准 |
| --- | --- |
| 分配约束 | 无权限或禁用人员不能被分配任务 |
| 编号唯一性 | 并发起草不会生成重复合同编号 |
| 流程测试 | 起草到签订、驳回重提路径均有自动化覆盖 |

### 3.3 P1：前端体验增强

目标：减少临时交互，提升演示质量。

交付项：

| 任务 | 内容 |
| --- | --- |
| FE-08 | 流程操作改为弹窗表单，不再使用 prompt |
| FE-09 | 用户、角色、合同表单增加更完整的前端校验 |
| FE-10 | 新增 403/404/空权限状态页面 |
| FE-11 | 合同详情增加编辑入口和状态流转时间线 |

## 4. 建议下一轮执行顺序

1. 先增加 GitHub Actions：后端测试、前端构建、MySQL profile 启动校验。
2. 再完善 JWT 退出/刷新策略和 Security 权限边界，避免后续接口重复调整。
3. 补合同流程人员校验和合同编号生成。
4. 用集成测试覆盖完整流程。
5. 最后做前端弹窗表单和部署打包。
